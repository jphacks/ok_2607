# 見た目と手ざわりの見直し（ゲームフィール）デザイン

2026-10-18。依頼者: @lovemeasure。共通 UI の担当 @ki-mutaku の確認を経てから実装に入る。

## 目的

TriOne を「シンプルだけど、触っていて気持ちいい」ゲーム的な ToDo にする。想定ユーザーは、短い刺激と即時のフィードバックに慣れた若い層（いわゆるドパガキ）。

いまの画面は紺 × ゴールドのピクセル RPG で世界観はまとまっているが、

- 落ち着いた RPG メニューの印象で、テンションが上がる瞬間がない
- 選ぶ・チェックする・クリアする瞬間の反応（演出・音・振動）がほぼ無い
- 3択のカードがすべて同じ見た目で、「何が引けたか」のワクワクが無い

参考にする体験は Balatro / Slay the Spire の報酬カード選択（カードが配られ、選ぶと気持ちよく弾ける）。

## ゴール

1. どの主要操作にも 0.5 秒以内に目に見える反応がある
2. 3択のカードに「レア度」があり、引いた瞬間に違いがわかる
3. 色と光で、今の画面より明らかに派手で楽しい印象になる
4. それでも 1 画面 1 主操作のシンプルさを保ち、タスク名が一番読みやすい

## やらないこと（MVP の外）

- ガチャ通貨、ログインボーナス、ショップ、実績バッジ一覧などの新しいゲームシステム
- キャラクター育成、アバターの着せ替え
- ランキングや他人との比較
- 新しい API・DB の変更（演出は既存のデータ `skippedCount`・`dueAt`・XP・レベルだけで作る）

## 失敗とみなすこと（動いても NG）

- 演出が長く、操作を待たされる（1 つの演出は 0.5 秒以内。クリア画面のみ 1.5 秒まで、タップでスキップできる）
- 光や揺れでタスク名が読みにくい
- 色が増えすぎて画面がうるさい
- `prefers-reduced-motion` の利用者に動きが出る
- 音が勝手に鳴り続けて止められない

## 制約

- Next.js 15 / Tailwind CSS v4 / DotGothic16 のまま。**新しい依存パッケージは追加しない**（アニメーションは CSS の `@keyframes`、音は Web Audio API で生成）
- 色は `src/app/tokens.css` のトークン経由。16 進数を画面に直接書かない（`docs/design.md`）
- 共通 UI（`tokens.css`、`globals.css`、`src/components/ui/`）は @ki-mutaku の担当。変更は共通ファイルだけの小さな PR を先に出す（`AGENTS.md`）
- スマホ縦型 390px 基準
- ドット絵の世界観（ピクセル枠、DotGothic16、既存のドット絵）は残す

## 決めたこと

### 1. 配色

紺から「紫寄りの黒 + ネオン」に寄せる。強調色はゴールド＋ネオン 2 色までに絞る。

| トークン（案）          | 色（目安）         | 用途                                               |
| ----------------------- | ------------------ | -------------------------------------------------- |
| `surface`（変更）       | `#120e22`          | 画面の背景。紫寄りの黒                             |
| `panel`（変更）         | `#1f1838`          | カード・パネル                                     |
| `gold` 系（維持）       | 現状のまま         | 主ボタン・XP・クリア。「報酬」の色                 |
| `neon-pink`（追加）     | `#ff4fd8` 付近     | 即決・コンボ・レベルアップなど一瞬の強調           |
| `neon-cyan`（追加）     | `#3ee8ff` 付近     | 進捗・チェック完了                                 |
| `urgent`（追加）        | `#ff6a3d` 付近     | 緊急クエストの枠と脈動                             |
| `rarity-common`（追加） | `neon-cyan` と同系 | 通常カードの枠                                     |
| `rarity-rare`（追加）   | `#a46bff` 付近     | レアカードの枠                                     |
| `rarity-mythic`（追加） | グラデーション     | 幻カードの枠（ゴールド → ピンク → シアンのホロ風） |

- 色の値は目安。最終値は @ki-mutaku が決め、本文とのコントラスト比 4.5:1 以上を守る
- 背景に薄い走査線（CRT 風）を重ねる。不透明度は 5% 程度で、文字の読みやすさを優先する

### 2. カードのレア度

reject された回数が多いタスクほど出にくい（`1 / (skippedCount + 1)`）ので、出てきたこと自体が「レア」として演出する。埋もれたタスクを拾うきっかけにもなる。

| レア度 | 条件（Claude の案）   | 見た目                                         |
| ------ | --------------------- | ---------------------------------------------- |
| 通常   | `skippedCount` 0〜1   | シアンの枠                                     |
| レア   | `skippedCount` 2〜4   | 紫の枠、表になる瞬間に一度光る                 |
| 幻     | `skippedCount` 5 以上 | ホロ枠がゆっくり流れる、表になる瞬間に強く光る |
| 緊急   | 緊急クエスト（1 択）  | `urgent` の枠が脈打つ。レア度より優先          |

- しきい値の判定は `src/features/quest/` に純粋関数で置き、テストする
- カードには「❌3」のような reject 回数ではなく、レア度のラベル（「レア」「幻」）を出す。回数は補足として小さく残してよい

### 3. 操作ごとの反応

| 瞬間                 | 演出                                                                                 | 画面の担当         |
| -------------------- | ------------------------------------------------------------------------------------ | ------------------ |
| 3択の表示            | カードが 1 枚ずつ 80ms 間隔で配られ、裏から表に返る（既存の `card-draw` を置き換え） | @ki-mutaku         |
| カードを選ぶ         | 選んだカードが少し拡大して光る。選ばなかったカードは灰色になり崩れて消える           | @ki-mutaku         |
| 3秒以内に選ぶ        | 「即決!!」のハンコ（既存の「⚡ 直感即決！」を置き換え）と画面の軽い揺れ              | @ki-mutaku         |
| チェックポイント完了 | `+10 XP` が飛び出して消える。進捗バーが 1 マスずつ埋まる                             | @miyagunimikihiro  |
| 連続で完了           | 10 秒以内に続けて完了すると「COMBO ×2」の表示（XP は増やさない。見た目だけ）         | @miyagunimikihiro  |
| クエストクリア       | XP の数字がカウントアップ。レベルが上がったら全画面フラッシュと「LEVEL UP!」         | @miyagunimikihiro  |
| タスク登録           | 一覧の先頭に新しいカードが「ポン」と出る                                             | @lovemeasure       |
| ボタン全般           | 押した瞬間に 2px 沈む（ピクセルの押し込み）                                          | @ki-mutaku（共通） |

- 演出の長さは 1 つ 0.5 秒以内。クリア画面だけ 1.5 秒までとし、タップでスキップできる
- `prefers-reduced-motion: reduce` では、動き（移動・揺れ・拡大・フラッシュ）を止める。色の変化と表示は残す

### 4. 音と振動

- 効果音は Web Audio API で短いピコ音を生成する（音声ファイルを置かない）。対象は「カードが表になる」「選ぶ」「チェック」「クリア」「レベルアップ」の 5 種類
- 画面上部に音のオン・オフを置き、設定は `localStorage` に保存する。読み書きは try/catch で囲み、失敗したら音なしとして動く
- 初期値はオン（Claude の案）。ただしブラウザの制約で、最初のタップまでは鳴らない
- 振動は `navigator.vibrate` がある端末（主に Android）だけ、選ぶ・クリアのときに 20〜40ms

### 5. 文言のトーン

短く、ゲームっぽく、テンポよく。例: 「今日の冒険を選べ」「即決!!」「COMBO ×2」「QUEST CLEAR!」「LEVEL UP!」。説明文は 1 行まで。

## 進め方（PR の分け方）

`AGENTS.md` のルールに従い、共通ファイルの PR を先に出してから各画面に適用する。

1. **このデザイン文書**（`docs/` のみ）: @ki-mutaku と内容を確認する
2. **トークン**（@ki-mutaku）: `tokens.css` の色の変更と追加、`docs/design.md` のトークン一覧の更新
3. **演出の共通部品**（@ki-mutaku）: `src/components/ui/` に次を追加し、テストを付ける
   - ボタンの押し込み（`PixelButton` の移行と合わせてよい）
   - `FloatingText`（`+10 XP` のような飛び出す文字）
   - `useSound`（効果音の再生とミュート設定）と `vibrate` の薄いラッパー
   - 揺れ・フラッシュ・カードを返すアニメーションは、Tailwind v4 の `--animate-*` と `@keyframes` として `tokens.css` の `@theme` に定義し、`animate-shake` のようなクラスで使う（`globals.css` に部品のクラスを足さないルールを守るため。Claude の案）
4. **各画面に適用**（担当ごとに 1 PR）: 3択とレア度 → @ki-mutaku、チェックポイント・クリア → @miyagunimikihiro、タスク一覧 → @lovemeasure

デモ直前は見た目が壊れる危険があるため、機能を優先して 2〜4 を止めてよい。

## 実装する人に任せること

- 各色の最終値（コントラスト比を守る範囲で）
- アニメーションのイージングと細かいタイミング（上限の時間は守る）
- 効果音の音程と波形
- 走査線を CSS で描くか画像にするか
- カードの裏面のデザイン
